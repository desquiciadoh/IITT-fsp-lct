## 1. Краткая инструкция (Быстрый старт за 1 минуту)

Для максимального удобства проверяющих весь стек разворачивается **ровно одной командой**:

### Linux / macOS
```bash
docker compose up --build
# или через скрипт:
./start.sh
```

### Windows (PowerShell)
```powershell
docker compose up --build
# или через скрипт:
.\start.ps1
```

### Доступ к запущенным сервисам:
* 🌐 **Веб-интерфейс платформы (SPA):** [http://localhost:5173](http://localhost:5173)
* 📡 **REST API:** [http://localhost:8000/api/](http://localhost:8000/api/)
* 📚 **Интерактивная Swagger/OpenAPI документация:** [http://localhost:8000/api/docs/](http://localhost:8000/api/docs/)
* ⚙️ **Django Административная панель:** [http://localhost:8000/admin/](http://localhost:8000/admin/)
* 📧 **Почтовый сервер для отладки (MailHog):** [http://localhost:8025](http://localhost:8025)

*База данных автоматически мигрирует и наполняется реалистичными демонстрационными данными (чемпионы ФСП, кандидаты разных грейдов, компании, вакансии, офферы).*

### Ключевые архитектурные принципы:
1. **Детерминированное адаптивное тестирование (CAT IRT):** оценка уровня знаний базируется на 3-параметрической логистической модели (3PL IRT: дискриминация $a$, сложность $b$, угадывание $c$) с апостериорным байесовским оцениванием (EAP). Исключено прямое судейство языковыми моделями.
2. **Безусловная защита контактов (Zero Contact Leaks):** персональные данные кандидатов шифруются алгоритмом AES-256-GCM. Доступ к контактам регулируется строгой сущностью `ContactGrant`, выдаваемой сервером исключительно при акцепте оффера соискателем. Любые попытки прямого чтения пресекаются кодом 403 с записью в журнал безопасности `AuditLog`.
3. **Зарплатная прозрачность:** в вакансиях и драфт-офферах обязательны минимальная и максимальная ставка (`salary_min`, `salary_max`), валидируемые как на уровне сериализаторов DRF, так и на уровне `CheckConstraint` в СУБД.
4. **Объяснимый скоринг (Explainable AI):** карточки кандидатов содержат прозрачные чипы `ReasonChips` с категоризацией источников фактов (`test` — подтверждено вступительным тестом, `fsp` — подтверждено Федерацией, `declared` — заявлено кандидатом).

## 3. Системные требования

### Для запуска через Docker (рекомендуется):
* Docker Engine 24+ и Docker Compose v2+
* 4 ГБ оперативной памяти (рекомендуется 8 ГБ)
* 5 ГБ свободного дискового пространства

### Для локального запуска без Docker:
* Python 3.12 или 3.13
* Node.js 20+ и менеджер пакетов `pnpm` (8+ или 9+)
* Сервер PostgreSQL 17 с установленным расширением `pgvector`
* Сервер Redis 7+

## 4. Варианты запуска

### Вариант А: Docker Compose (Рекомендуемый)

Развёртывание всего комплекса контейнеров (БД с pgvector, Redis, Django API с автомиграциями и сидом, воркеры Celery, Celery Beat, MailHog и Web Frontend на Nginx):

```bash
docker compose up --build
```

Для работы в фоновом режиме:
```bash
docker compose up --build -d
```

Для остановки:
```bash
docker compose down
```

Если необходимо сбросить базу и наполнить заново:
```bash
docker compose down -v
docker compose up --build
```

---

### Вариант Б: Локальный запуск без Docker

#### 1. Клонирование и подготовка окружения:
```bash
# Копирование переменных окружения
cp .env.example .env

# Создание и активация Python виртуального окружения
python -m venv .venv

# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установка зависимостей бэкенда
pip install --upgrade pip
pip install -r requirements.txt
```

#### 2. Запуск PostgreSQL и Redis:
Если локально не запущены службы PostgreSQL и Redis, их можно поднять одной командой через Docker:
```bash
docker run -d --name fsp-db -p 5432:5432 -e POSTGRES_DB=fsp_draft -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres pgvector/pgvector:pg17
docker run -d --name fsp-redis -p 6379:6379 redis:7-alpine
```

#### 3. Применение миграций и загрузка демо-данных:
```bash
python manage.py migrate
python manage.py seed
```

#### 4. Запуск сервера бэкенда:
```bash
python manage.py runserver 0.0.0.0:8000
```

#### 5. Установка и запуск фронтенда:
В отдельном окне терминала:
```bash
cd web
pnpm install
pnpm dev
```
Фронтенд будет доступен по адресу `http://localhost:5173`.

---

### Вариант В: Production / Staging деплой с Caddy и SSL

Для промышленного стенда в репозитории подготовлена конфигурация в каталоге `deploy/`:
* Автоматический выпуск Let's Encrypt SSL-сертификатов через Caddy (`deploy/Caddyfile`).
* Полноценная обработка SSE потоков (`flush_interval -1`).
* Изолированный контейнер автоматического резервного копирования базы данных (`deploy/backup.sh`).
* Защита cookies (`SESSION_COOKIE_SECURE=True`, `CSRF_COOKIE_SECURE=True`).

Запуск staging/production стенда:
```bash
cd deploy
docker compose -f docker-compose.staging.yml up -d --build
```

## 8. Пошаговый сценарий демонстрации для жюри

### Шаг 1: Главная страница и выбор роли
1. Откройте [http://localhost:5173](http://localhost:5173).
2. Нажмите кнопку демо-входа или перейдите в профиль работодателя / кандидата.

### Шаг 2: Прохождение адаптивного тестирования (Кандидат)
1. Войдите как новый кандидат или перейдите на страницу квалификационного теста (`/assessment` или `/qualification`).
2. Выберите специализацию (Backend, Frontend, ML/Data) и заявляемый грейд (Junior, Middle, Senior).
3. Пройдите адаптивное тестирование:
   - В Full-режиме выдается серия из 12 динамических вопросов.
   - Вопросы генерируются на лету параметрическими генераторами с детерминированным seed.
   - Система пересчитывает апостериорную оценку $\theta$ и погрешность $SE$ после каждого ответа.
4. По завершении теста система детерминированно определяет грейд (подтверждён / не подтверждён) и размещает профиль в соответствующей Лиге талантов.

### Шаг 3: Поиск талантов и изучение Лиг (Работодатель)
1. Переключитесь на роль работодателя (Yandex Tech или Сбер).
2. Перейдите в раздел **Поиск талантов / Скаутинг** (`/employer/talent-search` или `/employer/scouting`).
3. Изучите карточки кандидатов:
   - Обратите внимание на чипы обоснования (`ReasonChips`) с бейджами «✓ Verified Python» (источник: `test`), «🏆 Чемпион России» (источник: `fsp`).
   - Контакты кандидата (email, телефон, telegram) замаскированы.

### Шаг 4: Создание вакансии и отправка Драфт-оффера
1. Создайте позицию с обязательным указанием зарплатной вилки и типа налога (например: 350 000 — 450 000 ₽ gross).
2. Направьте адресный Драфт-оффер кандидату. Если предлагаемая зарплата ниже ожиданий кандидата, интерфейс выдаст предупреждение `below_floor`.
3. Попробуйте запросить контакты кандидата через API: сервер вернет `403 Forbidden` с описанием RFC 7807 `contact_not_granted`. Попытка доступа фиксируется в `AuditLog`.

### Шаг 5: Принятие оффера и открытие контактов
1. Войдите под кандидатом, получившим оффер, в разделе офферов (`/candidate/offers`).
2. Примите оффер нажатием кнопки **Принять оффер** (`accepted`).
3. Вернитесь в кабинет работодателя: контакты кандидата открываются автоматически через выданный сервером `ContactGrant`.

### Шаг 6: Карточка игрока (Player Card PDF)
1. В профиле кандидата нажмите **Скачать карточку игрока (PDF)**.
2. Сервер сгенерирует документ через WeasyPrint с водяными знаками компании, подтвержденными навыками и защитным QR-кодом верификации.

### Шаг 7: Психометрическая лаборатория (Lab Playground)
1. Откройте раздел интерактивной лаборатории [http://localhost:5173/lab](http://localhost:5173/lab).
2. Ознакомьтесь с психометрическими графиками:
   - Характеристические кривые заданий (Item Characteristic Curves, ICC).
   - Информационная функция теста (Test Information Function, TIF).
   - Распределение параметров сложности и дискриминации по банку вопросов.
   - Результаты калибровки и цифровые двойники (Twins) параллельных форм тестов.

## 9. Диагностика и решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| Ошибка `Port 5432 already in use` | Локально запущен другой PostgreSQL | Остановите локальную службу или укажите `POSTGRES_PORT=5433` в `.env` |
| Ошибка `403 CSRF verification failed` | Запрос с недоверенного Origin | Убедитесь, что ваш адрес указан в `CSRF_TRUSTED_ORIGINS` (по умолчанию `localhost:5173`) |
| Ошибка `KeyError: SECRET_KEY` | Не заданы переменные окружения | Выполните `cp .env.example .env` или используйте `docker compose up --build` с встроенными fallbacks |
| Воркер Celery не запускается | Redis недоступен | Проверьте статус Redis: `docker compose ps redis` или `redis-cli ping` |
| Ошибка `429 Cooldown active` | Прошло менее 30 дней с последней попытки теста | Вызовите эндпоинт `POST /api/demo/time-travel` с телом `{"days": 30}` для сдвига часов |
