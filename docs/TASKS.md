# TASKS: FSP Draft implementation plan

> Companion to [ARCHITECTURE.md](ARCHITECTURE.md). **Part 1** is the foundation every stream codes against: repo layout, runtime, data model, API contracts and internal interfaces. **Part 2** is the tracker: four parallel streams with dependencies, priorities, and the mocks that let everyone start on day 1.

**How to use this file**
- Claim a task by adding your initials after its ID (`BE-05 [AK]`). Tick the box in the PR that finishes it.
- **P0** must ship (golden path or mandatory deliverable). **P1** multiplies the score; start it once your stream's P0s for the current milestone are done. **P2** is docs/concept only (§2.9).
- **Size:** S ≤ ½ day · M = 1–2 days · L = 3+ days. A mock (`MKn`, §2.2) can satisfy a dependency early. **Done** is the acceptance check.

Indexes: `league_memberships(specialization, grade, status)`, `offers(candidate_id, status)`, `offers(company_id, status)`, `assessments(candidate_id, started_at desc)`, `candidate_skills(skill_id)`. HNSW on the embedding columns comes with AI-11.

**Invariants.** These are enforced in code, and BE-14 covers them with tests.
1. **Visibility.** A candidate appears in pools and search only if the email is verified, `publication` consent is granted, `open_to_offers` is true, the league status is not `pending`, and the viewer's company isn't in `blocked_company_ids`. This is one SQL function, used everywhere.
2. **Contacts.** They are read only through `ContactAccess.get(company_id, candidate_id)`, which requires an active grant and writes an audit row.
3. **Offer status** changes only through the state machine. `UPDATE … WHERE id = :id AND version = :v` touching 0 rows means `409 version_conflict`.
4. **Answer keys.** `assessment_items.key` is selected only by the grading path, and no API schema has a key field.
5. **Time.** Every "now" in cooldown logic is `now() + clock_offset_days`. The offset is non-zero only in DEMO_MODE.

### 1.4 API contract (frontend ⇄ backend)

**Conventions**
- Base path `/api`, JSON, snake_case. IDs are UUIDs, except candidates on the employer side, who are addressed by `public_id`.
- Auth uses an HttpOnly session cookie `sid` (SameSite=Lax). Unsafe methods must send `X-Requested-With: fsp-draft` (CSRF guard).
- Errors are `application/problem+json` with a machine-readable `code` (catalog below). A 422 also carries `errors[{field, msg}]`.
- Lists take `?page=1&size=20` (max 100) and return `{items, total, page}`. Array filters repeat the key: `?grades=middle&grades=senior`.
- Money is an integer number of RUB per month, always with `type: gross` or `net`. Times are ISO 8601 UTC.
- A route that isn't implemented yet returns fixture JSON in its final shape, with the header `X-Stub: true` (MK1).

### 1.5 Internal interfaces (Integrations/AI ⇄ Backend)

Backend owns I/O and persistence. Integrations/AI owns pure logic behind these signatures, so both sides build in parallel and the validation scripts reuse the exact production code. Changing a signature means one PR that touches both sides.

```python
# apps/api/families/base.py: what every item family provides
class FamilyMeta(BaseModel):
    id: str; version: int; specs: list[Spec]; topic: str; skills: list[str]
    format: ItemFormat; a: float; b: float; c: float; time_limit_s: int

class Instance(BaseModel):
    stem_md: str
    code: Code | None = None                 # Code(lang, text)
    options: list[Option] | None = None      # already shuffled; option ids are opaque
    input: Literal["choice", "number", "text"]
    key: Key                                 # stays server-side (assessment_items.key)
    fingerprint: str                         # hash of the drawn parameters → collision stats

class ItemFamily(Protocol):
    meta: FamilyMeta
    def generate(self, rng: random.Random) -> Instance: ...
    def is_correct(self, inst: Instance, answer: Answer) -> bool: ...
    def oracle(self, inst: Instance) -> Key: ...   # independent recomputation; used only by families.verify

# apps/api/app/modules/assessment/engine/: pure, no I/O (validation/ imports it too)
class CatEngine(Protocol):
    def start(self, spec: Spec, claimed: Grade, mode: Mode,
              pool: list[FamilyMeta], seen: set[str]) -> CatState: ...
    def next_family(self, state: CatState) -> FamilyMeta | None: ...    # None → stop
    def record(self, state: CatState, family_id: str, correct: bool) -> CatState: ...
    def result(self, state: CatState) -> CatResult: ...  # θ, SE, rating, grade, decision, promotion, fallback, topics
# CatState is a pydantic model, persisted as assessments.state (jsonb)

# apps/api/app/modules/matching/: pure
def score_pool(need: NeedCtx, pool: list[CandidateCtx], weights: Weights) -> list[Scored]: ...  # Scored ↔ PoolItem
def strength(c: CandidateCtx, league: LeagueStats) -> float: ...
def relaxations(need: NeedCtx, pool: list[CandidateCtx]) -> list[Relaxation]: ...              # P1 (AI-12)

# apps/api/app/llm/gateway.py: FakeLlm (rules) and GigaChatLlm implement it
class LlmGateway(Protocol):
    async def resume(self, redacted_text: str) -> ResumeDraft: ...
    async def jd(self, text: str) -> JdDraft: ...
    async def phrase(self, facts: list[str]) -> str: ...
# Any exception → the caller falls back to FakeLlm. Grading never calls an LLM.
```

### 2.10 Definition of Done & working agreements

**Every task is done when:**
- It is merged to `main` through a PR with green CI. The PR title starts with the task ID, and the box here is ticked in the same PR.
- New or changed endpoints have final Pydantic schemas, an example and their error codes, and `make openapi client` output is committed.
- Pure logic (engines, scorer, families) has unit tests with fixed seeds.
- It works on staging (after M1), and the matching `docs/` section is updated. The TK grades code/docs consistency.

**Working agreements**
- **Contract first.** Change a schema → regenerate → commit both → tell the other side. Breaking changes get a heads-up in the team chat first.
- **Stubs are loud.** They carry `X-Stub: true`. By M1 no P0 route may return it, and FE-19 asserts this.
- **Small PRs** (under ~400 lines), trunk-based, with staging deploying from `main`.
- **Daily 15-minute sync** on blockers and mock swaps. PD keeps this file current.
- **Cut rule.** A P1 task not merged by M2 −2 days is cut and documented as roadmap; no heroics during the freeze.
