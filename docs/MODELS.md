## 1. Фундаментальные принципы и инварианты

1. **Никаких LLM в скоринге и грейдинге**: Ни одна генеративная модель не принимает решений об оценках, лигах, рейтинге или ранжировании кандидатов. Все оценки рассчитываются строго детерминированно по математическим моделям IRT/CAT (ML-модуль).
2. **152-ФЗ (Локальная деперсонализация)**: Перед любой передачей данных во внешние API текст резюме и вакансий проходит строгую локальную очистку через модуль `apps/llm_gateway/redact.py`. ФИО, номера телефонов, email, ссылки на профили (GitHub, LinkedIn, HH) и Telegram-аккаунты полностью вырезаются и заменяются служебными токенами (`[EMAIL]`, `[PHONE]`, `[NAME]`, `[TG]`, `[URL]`).
3. **Отказоустойчивость (Graceful Degradation)**: Любой сбой внешнего API (сетевой таймаут, rate limit, невалидный JSON) мгновенно и прозрачно переключается на детерминированный эвристический движок `FakeLlm`.
4. **Конфиденциальность в логах**: В логи запрещено выводить исходный текст запросов и ответов моделей; логируются только хэш запроса `sha256`, провайдер, статус кэша и задержка (latency).

## 2. Реестр используемых моделей

| Модель | Назначение | Контур исполнения | Входные данные | Фоллбэк (Fallback) | Версия промпта |
|---|---|---|---|---|---|
| **GigaChat-2** | Анализ резюме и предзаполнение профиля кандидата | Внешнее API (ПАО Сбербанк, РФ) | **Только деперсонализированный текст** (без ПДн) | `FakeLlm` (правила + регулярные выражения) | `resume.v1.md` |
| **GigaChat-2** | Анализ описания вакансии (JD) и разделение навыков must/nice | Внешнее API (ПАО Сбербанк, РФ) | Текст вакансии (контакты компании маскируются) | `FakeLlm` (правила + таксономия) | `jd.v1.md` |
| **GigaChat-2** | Формулирование 1–2 связных предложений обоснования оффера («Why you») | Внешнее API (ПАО Сбербанк, РФ) | **Только факты скоринга** (без персональных данных) | Детерминированный строковый шаблон | `phrase.v1.md` (с валидацией чисел) |
| **GigaChat-2-Pro / Max** | Офлайн-генерация черновиков семейств задач и пулов дистракторов (MCQ) | Офлайн-скрипты (`tools/draft_families/`) | Описания тем из спецификаций | Ручная разработка ML-инженером | Офлайн |
| **USER-bge-m3** | Семантические эмбеддинги для сопоставления профилей и редких синонимов | Локальный инференс (ML-контур) | Канонические названия навыков и тем | Лексический поиск `rapidfuzz` | — |

## 3. Переменные окружения (Environment Variables)

Для управления поведением LLM Gateway используются следующие переменные в файле `.env`:

| Переменная | Тип | По умолчанию | Описание |
|---|---|---|---|
| `LLM_PROVIDER` | string | `fake` | Активный провайдер (`fake` для локальной разработки и CI, `gigachat` для боевого контура). |
| `GIGACHAT_AUTH_KEY` | string | `null` | Base64-ключ авторизации Client ID + Client Secret для GigaChat OAuth. |
| `GIGACHAT_SCOPE` | string | `GIGACHAT_API_PERS` | Область действия API (`GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_CORP` для юрлиц). |
| `GIGACHAT_MODEL` | string | `GigaChat-2` | Имя целевой модели в GigaChat API. |
| `GIGACHAT_CA_BUNDLE` | path | `null` | Путь к сертификатам Минцифры РФ (Russian Trusted Root CA). Проверка TLS включена всегда. |
| `LLM_TIMEOUT_S` | float | `10.0` | Таймаут HTTP-запроса к API в секундах (после чего выполняется 1 повтор или переход на фоллбэк). |
