## 1. Фундаментальные принципы и инварианты

1. **Никаких LLM в скоринге и грейдинге**: Ни одна генеративная модель не принимает решений об оценках, лигах, рейтинге или ранжировании кандидатов. Все оценки рассчитываются строго детерминированно по математическим моделям IRT/CAT (ML-модуль).
2. **152-ФЗ (Локальная деперсонализация)**: Перед любой передачей данных во внешние API текст резюме и вакансий проходит локальную очистку в `apps/llm_gateway/redact.py`: email, телефоны, Telegram (ссылки, подписанные ники, `@handle`), ссылки на профили и личные сайты (включая поддомены вида `ivanov.github.io`), ФИО в шапке, после подписей («ФИО:», «Рекомендации:», «Контактное лицо:») и в любом месте текста (по словарю имён и отчеств, со склонениями). Всё заменяется токенами `[EMAIL]`, `[PHONE]`, `[NAME]`, `[TG]`, `[URL]`. Затем `assert_clean()` повторно проверяет текст более широкими шаблонами и ищет в нём каждое найденное значение; если что-то осталось, LLM не вызывается (`fallback_reason = "pii_residual"`). Модель для поиска имён не используется: словарь `pii_lexicon.py` работает локально.
3. **Отказоустойчивость (Graceful Degradation)**: Любой сбой внешнего API (таймаут, rate limit, 5xx, невалидный JSON после одной попытки исправления, исключение в адаптере) переключает ответ на детерминированный движок `FakeLlm` в оркестраторе (`apps/llm_gateway/pipeline.py`); результат помечается `source = "rules"` и причиной. В кэш (7 дней, ключ `sha256(kind|prompt|model|text)`) попадает только проверенный ответ LLM.
4. **Конфиденциальность и наблюдаемость в логах (AI-R12)**: В логи не попадают тексты резюме и вакансий, ответы моделей и тексты исключений (только `type(e).__name__`). На каждый вызов `parse_resume`, `parse_jd` и `phrase` модуль `apps/llm_gateway/obs_logging.py` пишет одну запись `llm_call` (`logger="llm_gateway"`, поля в `extra`):
   - `kind`: тип операции (`resume` | `jd` | `phrase`)
   - `provider`: активный провайдер (`fake` | `gigachat`)
   - `model`: имя модели (для `fake` — `fake`)
   - `prompt`: версия системного промпта (`resume.v2`, `jd.v1`, `phrase.v1`)
   - `input_hash`: первые 12 символов `sha256` от обезличенного входного текста
   - `latency_ms`: время выполнения вызова в миллисекундах
   - `cache_hit`: флаг попадания в кэш (`True` | `False`)
   - `source`: источник результата (`llm` | `rules`)
   - `fallback_reason`: почему ответили правила — `provider_fake` (провайдер `fake`), `provider_unknown` (неизвестное значение `LLM_PROVIDER`), `no_key` (нет `GIGACHAT_AUTH_KEY`), `pii_residual` (для `phrase` — ПДн в самих фактах), `timeout`, `http_error`, `schema`, `error` (исключение в адаптере); для `phrase` также `grounding_<проверка>` (`length`, `sentences`, `placeholder`, `numbers`, `skills`); для `jd` суффикс `+blueprint`, если упала функция ML `blueprint_for`; `None`, если ответила LLM.

## 2. Реестр используемых моделей

| Модель | Назначение | Контур исполнения | Входные данные | Фоллбэк (Fallback) | Версия промпта |
|---|---|---|---|---|---|
| **GigaChat-2** | Анализ резюме и предзаполнение профиля кандидата | Внешнее API (ПАО Сбербанк, РФ) | **Только деперсонализированный текст** (без ПДн) | `FakeLlm` (правила + регулярные выражения) | `resume.v2.md` |
| **GigaChat-2** | Анализ описания вакансии (JD) и разделение навыков must/nice | Внешнее API (ПАО Сбербанк, РФ) | Текст вакансии (контакты компании маскируются) | `FakeLlm` (правила + таксономия) | `jd.v1.md` |
| **GigaChat-2** | Формулирование 1–2 связных предложений обоснования оффера («Why you») | Внешнее API (ПАО Сбербанк, РФ) | **Только факты скоринга** (без персональных данных) | Детерминированный строковый шаблон | `phrase.v1.md` (с валидацией чисел и навыков; без фактов — пустая строка; принятые фразы кэшируются по sha256 версии промпта, модели и фактов) |
| **GigaChat-2-Pro / Max** | Офлайн-генерация черновиков семейств задач и пулов дистракторов (MCQ) | Офлайн-скрипты (`tools/draft_families/`) | Описания тем из спецификаций | Ручная разработка ML-инженером | Офлайн |
| **USER-bge-m3** | Семантические эмбеддинги для сопоставления профилей и редких синонимов | Локальный инференс (ML-контур) | Канонические названия навыков и тем | Лексический поиск `rapidfuzz` | — |

*Примечание:* Грейдинг, ранжирование и расчет позиций в лигах осуществляются исключительно детерминированными математическими методами IRT без участия нейросетевых моделей.

## 3. Переменные окружения (Environment Variables)

Для управления поведением LLM Gateway используются следующие переменные в файле `.env`:

| Переменная | Тип | По умолчанию | Описание |
|---|---|---|---|
| `LLM_PROVIDER` | string | `fake` | Активный провайдер (`fake` для локальной разработки и CI, `gigachat` для боевого контура). |
| `GIGACHAT_AUTH_KEY` | string | `null` | Base64-ключ авторизации Client ID + Client Secret для GigaChat OAuth. |
| `GIGACHAT_SCOPE` | string | `GIGACHAT_API_PERS` | Область действия API (`GIGACHAT_API_PERS` для физлиц, `GIGACHAT_API_CORP` для юрлиц). |
| `GIGACHAT_MODEL` | string | `GigaChat-2` | Имя целевой модели в GigaChat API. |
| `GIGACHAT_CA_BUNDLE` | path | `null` | Путь к сертификатам Минцифры РФ (Russian Trusted Root CA). Проверка TLS включена всегда. |
| `LLM_TIMEOUT_S` | float | `10.0` | Общий бюджет одного вызова в секундах: OAuth, запрос, один повтор (таймаут, сеть, 429, 5xx) и одна попытка исправления JSON. Каждый HTTP-запрос ограничен `min(остаток, 8)` с. Укладывается в 15 с ожидания BE. |
