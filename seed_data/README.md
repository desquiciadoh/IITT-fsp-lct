# seed_data/full: synthetic world (ML-7)

Generated by `python -m validation.synth --seed 2026` (repo root). It is a deterministic function of
the seed (`manifest.json` holds the seed, counts and a sha256 per file), and the as-of date is fixed
at 2026-10-10 12:00 UTC so recency features are reproducible. BE loads it with `seed --mode=full`
(BE.md N8). The hidden truth (`validation/data/truth.jsonl`) is for validation only: the app must
never read it.

All files are UTF-8 JSON Lines (one object per line, keys sorted). Enum values match `core.enums`.
Names and e-mails are synthetic (`@example.com`); company names and domains are fictional
(`.example`). There is no personal data.

| `city`, `timezone` | str | |

## assessments.jsonl: one finished qualification per tested candidate (~92 %)

Run through the production `IrtCatEngine`; answers were simulated from the candidate's true θ on
perturbed item parameters (`validation/simulate.py`).

| Field | Notes |
|---|---|
| `public_id`, `specialization`, `claimed_grade`, `kind` (`initial`), `mode` (`full`) | |
| `families` | family ids in the order served (no instances or keys: those are per-session secrets) |
| `theta`, `se`, `rating`, `rating_ci` | `rating = round(1000 + 200·θ)` |
| `result_grade`, `decision`, `promotion_unlocked`, `fallback_grade`, `complete`, `stop_reason` | `CatResult` fields |
| `topics` | `[{topic, level}]` with level `strong` \| `moderate` \| `limited` |
| `evidence` | `[{seq, level, correct}]` |
| `finished_at` | ISO date |

## leagues.jsonl: one league membership per tested candidate

`public_id`, `specialization`, `grade` (the claimed grade), `status` (`confirmed` \| `unconfirmed`),
`theta`, `se`, `rating`, `topic_levels` (`{topic: level}`), and `percentile`, `base_strength`,
`fsp_boost`, `strength` computed by `matching.engine.strength.strength()` over the league's θ.

## fsp_registry.jsonl: FSP registry payload per linked participant (~32 %)

The contract of ARCHITECTURE §2.8 plus `public_id` and `rank`:
`participant_id` (`FSP-NNNNNN`), `sports_rank` (`{title: cat3 | cat2 | cat1 | kms | ms, awarded_at}` or
null), `results[]` (`event_id`, `event_name`, `date`, `discipline` ∈ algorithmic, product, infosec,
robotics, uas; `stage`, `format` (`team` \| `individual`), `team` (`{name, size}` or null),
`placement`, `placement_tier` ∈ winner, prize_winner, finalist, participant; `participants_total`),
`issued_at`, `signature` (sha256 of the payload; a mock, the real registry signs). FSP history is
more likely, and better placed, for higher θ. BE's `fsp-id-mock` can serve these rows.

## companies.jsonl (12) and positions.jsonl (60)

Companies: `company_id`, `name`, `domain`, `trust_level`, `budget_factor`. Positions: `position_id`,
`company_id`, `title`, `specialization`, `grades`, `allow_adjacent`, `must_skills`, `nice_skills`
(skill ids, disjoint), `work_formats`, `location`, `salary_min`, `salary_max`, `salary_type`, `preset`,
`description` (Russian JD text).

## manifest.json

`schema_version`, `seed`, `as_of`, `counts`, `sha256` per file and `truth_sha256`.

## validation/data/truth.jsonl (hidden)

`public_id`, `specialization`, `theta` (true ability), `true_grade`, `inflation`, `proficiency`
(`{skill_id: 0..1}`), `claimed_grade`, `tested`, `hero`. Only `validation/` reads it, to build the
relevance oracle of the matching benchmark (ML-8).
